# 홈페이지 리디자인 설계 — C 방향 (위쪽 메뉴 · 종이색 · 얇은 선)

- 작성일: 2026-11-27
- 대상 사이트: https://diudiuus.github.io (Astro 정적 사이트, GitHub Pages)
- 앞선 설계: `docs/superpowers/specs/2026-11-26-homepage-design.md` (내용·언어·프라이버시 규칙은 그대로 유효)
- 상태: 사용자 검토 대기

> 표기 규칙: **[결정]** 사용자가 직접 고른 것 · **[제안]** Claude가 정했고 사용자가 아직 따로 확인하지 않은 것 · **[빌더]** 만드는 사람이 정해도 되는 것

## 1. 왜 바꾸는가

- 지금 디자인(왼쪽 잉크색 사이드바 + 흰 박스 카드)은 흔한 포트폴리오 템플릿처럼 보여서 **평범하다**는 것이 사용자의 판단이다. **[결정]**
- 목적은 그대로다. 2027년 **해외 산업계 Data Scientist** 구직이 목적이고, 원칙은 "일목요연", "스크롤 적게", "깔끔하지만 개성 있게"다.
- 이번에 새로 확인한 원칙이 있다. **글씨가 너무 크면 한눈에 안 들어와서 읽는 사람이 힘들다.** 멋보다 읽기 편한 크기가 먼저다. **[결정]**

## 2. 목표 · 비목표 · 안티목표

### 목표
- 사이드바를 없애고, **모든 페이지 위쪽에 얇은 메뉴 줄**을 둔다. **[결정]**
- 바탕은 **따뜻한 종이색**으로 하고, 흰 박스 카드 대신 **얇은 선**으로 항목을 나눈다. 장미색은 포인트로 쓴다. **[결정]**
- 글씨는 **읽기 편한 크기**로 한다(4절의 크기 표). **[결정]**
- 넓은 화면을 활용한다. 노트북 화면(약 1440×900)에서 **About이 거의 한 화면에** 들어와야 한다. **[결정]**

### 비목표
- 문구는 바꾸지 않는다. 예외는 5절에 적은 새 문구 두 개(About의 "Research" 한 줄, Projects 부제)뿐이다.
- 새 기능(⌘K 검색, 풍력 터빈 등)은 넣지 않는다.
- 언어 규칙은 바꾸지 않는다. 한국어 페이지도 메뉴·페이지 제목·가치 키워드는 영어를 유지한다.

### 안티목표 (기술적으로 돌아가도 실패로 본다)
- **큰 히어로 문장**, 또는 한눈에 안 들어오는 큰 글씨 **[결정: 사용자가 큰 문장을 빼라고 함]**
- 지난번에 고르지 않은 "고급스러운" 시안의 요소 **[제안]**
  - 번호 매긴 항목(01, 02…)
  - 필기체 서명
  - 노이즈 질감
  - 맨 위 작은 kicker 문구
- 나를 그래프나 분포로 표현하는 것 (앞선 설계의 규칙)
- 토글이나 숨겨진 내용. 모든 항목은 펼쳐져 있다. (앞선 결정)

## 3. 고른 방향과 다른 후보

| 후보 | 내용 | 결과 |
|---|---|---|
| A. Bento | 크기가 다른 타일을 한 화면에 배치 | 고르지 않음 |
| B. Ink Night | 사이트 전체를 잉크색으로, 마우스를 따라오는 장미색 빛 | 고르지 않음 |
| **C. Big Type** | 사이드바 없이 위쪽 메뉴, 종이색, 큰 제목 목록 | **선택. 단 큰 문장은 빼고 글씨는 줄인다 [결정]** |
| (그 전) 같은 구조에 문장·색만 보강 | 사이드바 유지 + 큰 문장 + 2단 + 장미색 | 사용자가 "다른 방향"을 택함 |

- **승인된 시안:** `docs/superpowers/mockups/2026-11-27-c-compact.html` (About, Projects)
- **참고 시안:** `docs/superpowers/mockups/2026-11-27-c-pages.html` (Life & Values, 휴대폰). 이 파일은 글씨가 크게 그려져 있다. 크기는 4절 표를 따른다.
- 두 시안의 사진은 미리보기 서버(`/files/profile.jpg`)에서만 보인다. 실제 사진은 `public/images/profile.jpg`다.

**만드는 방법은 하나가 합리적이다.** 지금 Astro 구조를 유지하면서 레이아웃 컴포넌트와 CSS를 바꾼다. 사이드바는 마크업 구조 자체가 달라서 CSS만으로는 바꿀 수 없다. 새 프레임워크나 라이브러리는 필요 없다.

## 4. 공통 디자인

### 색 [결정: 시안 승인]

| 역할 | 값 | 비고 |
|---|---|---|
| 바탕(종이) | `#F7F4EF` | |
| 글자(잉크) | `#1B2238` | |
| 보조 글자 | `#4A5068` (설명) / `#686C7E` (라벨·날짜·메뉴·요약) | 아래 "읽기 기준" 참고 |
| 선 | `#DCD7CE`, `#E3DDD3` | 섹션 머리 선은 잉크색 1px |
| 장미색 | `#E895A8` | 밑줄, 그림자, 마침표, "Kim" |
| 장미색 글자 | `#C27387` | 18px 이상 글자나 hover에만 쓴다. 작은 글자에는 대비가 부족하다 **[빌더: 대비 확인]** |

- 기존 잉크색 사이드바 배경은 없어진다. 잉크색은 글자와 CV 버튼에만 남는다.
- **작은 글자의 보조색은 읽기 기준을 맞춘다. [제안: "읽기 편해야 한다"는 원칙에 따름]**
  - 시안의 `#8A8C99`(종이 바탕 대비 약 3.0:1)와 `#6C7082`(약 4.47:1)는 작은 글자에 쓰기에는 흐리다.
  - 라벨, 날짜, 메뉴, 요약 같은 **글자**에는 `#686C7E`(약 4.7:1, 접근성 기준 AA 충족)를 쓴다.
  - `#8A8C99`는 선이나 장식처럼 글자가 아닌 곳에만 남긴다. 눈으로 보이는 차이는 아주 작다.

### 글씨 크기 [결정: "읽기 편한 크기" 시안 승인]

| 요소 | 크기 · 글꼴 |
|---|---|
| 본문 | 15px DM Sans (한국어는 Pretendard) |
| About의 이름 | 34px Fraunces 450 |
| 페이지 제목 (Projects 등) | 32px Fraunces 450 |
| 항목 제목 (프로젝트·경력·논문) | 18–19px Fraunces 450 (한국어는 Gowun Batang) |
| 요약 한 줄 | 14.5px |
| 세부 (문제·접근 등) | 13–13.5px |
| 작은 대문자 라벨 | 10–10.5px, 자간 0.16–0.18em |

- 글꼴 조합은 그대로다. Fraunces + DM Sans, 한국어는 Gowun Batang + Pretendard다. "Kim"은 기울이지 않고 장미색만 쓴다.

### 위쪽 메뉴 줄 (모든 페이지) [결정]
- **왼쪽:** "Jiwoo Kim" (Fraunces 17px, "Kim"은 장미색). 누르면 About으로 간다.
- **가운데~오른쪽:** 메뉴 5개(About · Projects · Research · Experience · Life & Values)를 둔다. 현재 탭은 잉크색 글자에 장미색 밑줄이다.
- **맨 오른쪽:** EN · KO 전환과 CV 버튼(잉크색 바탕의 둥근 버튼)을 둔다.
- 아래에 얇은 선을 긋는다.
- 스크롤해도 위에 붙어 있는다(sticky). 넓은 화면과 휴대폰 모두 해당한다. **[제안]**
  - 이유 1: 어느 위치에서든 메뉴와 CV에 바로 닿는다.
  - 이유 2: 메뉴 줄이 화면 밖으로 밀려나지 않아서, 페이지 전환 때 메뉴가 위에서 날아들어 오는 이전 버그가 생길 여지가 없다.

### 작은 라벨의 언어 [제안: 지금 사이트의 규칙을 그대로 따름]
- 영어로 고정하는 것은 **메뉴, 페이지 제목, 가치 키워드**뿐이다(앞선 결정).
- 그 밖의 작은 라벨은 한국어 페이지에서 **지금처럼 한국어**로 쓴다. 지금 쓰는 라벨은 지금 · 다음 · 거주 · 기술 · 언어 · 대표 프로젝트 · 문제 · 접근 · 경력 · 학력 등이다.

- 영어 라벨에만 대문자와 넓은 자간을 쓴다. 한국어 라벨은 대문자 변환 없이 약 12px 보통 굵기로 쓴다.

## 5. 페이지별 디자인

### About [결정: 시안 승인]
- **머리:**
  - 왼쪽에 사진을 둔다. 148px 정사각형에 장미색 오프셋 그림자 8px다.
  - 오른쪽에 이름(h1), 직함, 소속, 소개 문단(15px, 최대 약 640px)을 둔다.
  - 한국어 페이지는 이름 위에 한글 이름 "김지우"를 작게 둔다(지금 사이드바와 같다). **[제안]**
- **사실 한 줄:** Now · **Research** · Next · Based in을 위아래 얇은 선 사이에 둔다.
  - "Research"는 새 항목이다. `profile.yaml`에 짧은 필드를 추가한다(예: `focus`). 값은 EN "Graph anomaly detection", KO "그래프 이상탐지"다. **[제안]**
  - 한국어 페이지의 라벨은 지금 · **연구** · 다음 · 거주다. **[제안]**
- **아래 두 칸:**
  - 왼쪽은 Featured projects 3개다. 행마다 제목, 기간, 한 줄 요약이 **항상 보인다**. 행을 누르면 Projects 페이지의 해당 항목으로 간다. 오른쪽 위에 "See all →"을 둔다.
  - 오른쪽(약 300px)은 Skills 칩(테두리만 있는 칩)과 Languages다.
- 페이지 제목 "About"은 따로 두지 않는다. 이름이 그 자리를 대신한다. **[결정: 시안]**

### Projects [결정: 시안 승인]
- **제목과 부제:** 페이지 제목 "Projects" 아래에 부제 한 줄을 둔다. **[제안: 새 문구]**
  - EN: "Data and AI systems built in industry, 2021–2025."
  - KO: "산업 현장에서 만든 데이터·AI 시스템, 2021–2025."
- **머리 선:** 프로젝트 수 라벨 + 잉크색 선을 둔다. **[제안]**
  - 라벨은 프로젝트 수에서 자동으로 만든다(EN "5 projects", KO "프로젝트 5개"). 프로젝트를 추가해도 틀리지 않게 하기 위해서다.
  - 시안에 있던 "Newest first"는 뺀다. 실제 순서가 날짜순이 아니라 `order` 값 순이기 때문이다.
- **항목:** 2단으로 나눈다.
  - 왼쪽(약 300px)은 제목과 회사·기간이다.
  - 오른쪽은 요약, Problem / Approach / (있으면) Result, 태그, 링크다.
  - 항목 사이는 얇은 선으로 나눈다.
- **hover:** 넓은 화면에서 마우스를 올리면 제목이 장미색이 되고 오른쪽으로 6px 움직인다. 휴대폰에서는 없다.
- `#프로젝트id` 링크(About과 Experience에서 들어오는 링크)는 그대로 동작해야 한다.

### Experience [제안: Projects와 같은 형식]
- 두 섹션으로 나눈다. 섹션 이름은 지금 그대로다(EN Experience / Education, KO 경력 / 학력). 섹션 머리는 작은 라벨 + 잉크색 선이다.
- 항목은 2단이다.
  - 왼쪽은 역할과 회사·기간이다.
  - 오른쪽은 설명, 위치, 관련 프로젝트 링크다.

### Research [제안: 같은 형식]
- Current research 문단, Interests 칩, Publications를 둔다.
- 논문은 2단이다. 왼쪽은 제목과 학술지·연도, 오른쪽은 저자, 요약, DOI와 링크다.

### Life & Values [제안: 참고 시안을 줄인 크기]

- **Hobbies와 Tastes:** 두 칸에 목차처럼 한 줄씩 둔다.
  - 왼쪽에 작은 대문자 라벨, 오른쪽에 값(Fraunces 약 16px)을 둔다.
  - Hobbies에는 번호를 붙이지 않는다.

## 6. 휴대폰 (폭 767px 이하) [제안: 참고 시안 기반]
- **위쪽 첫 줄:** 이름, EN · KO, CV를 둔다.
- **둘째 줄:** 메뉴 한 줄을 둔다. 가로로 스와이프해서 넘기고, 스크롤바는 숨긴다. 현재 탭은 장미색 밑줄이다.
- **About:**
  - 사진(약 96px), 이름, 직함, 소개 순서로 둔다.
  - 사실 네 개는 2×2로 둔다.
  - 그 아래 프로젝트 목록, 기술 칩, 언어가 온다.
- **2단 항목은 1단으로** 접힌다. Values 네 칸은 2×2나 1단으로 접는다. **[빌더]**
- 한국어 글은 단어 중간에서 줄이 바뀌지 않게 한다(`word-break: keep-all`, 지금도 적용 중).

## 7. 움직임 [결정: 앞서 만든 효과 유지]
- **페이지 전환(View Transitions):** 메뉴 줄은 제자리에 있고 본문만 바뀐다. 장미색 밑줄(현재 탭 표시)은 탭 사이를 미끄러지듯 이동한다. 휴대폰에서도 메뉴 줄이 날아들어 오면 안 된다(이전 버그).
- **등장 효과:** 0.7초 동안 떠오르고 70ms씩 차례로 나타난다. 대상은 항목 행, 가치, 취향, 섹션 머리, 사실 줄, 칩 묶음이다. 항목 안에 든 칩은 항목과 함께 움직인다.
- **동작 줄이기:** 이 설정을 켠 사람, JavaScript가 없는 환경, 인쇄할 때는 지금처럼 아무것도 숨기지 않는다.

## 8. 지켜야 할 기존 제약 (앞선 설계와 이번 세션의 결정)
- EN이 기본이고 KO는 `/ko/`다. 같은 탭에서 언어를 전환한다. 한국어 문구가 없으면 영어로 대체한다.
- 프라이버시
  - 전화번호는 어디에도 없어야 한다.
  - 이메일은 난독화한다.
  - CV는 전화번호를 뺀 파일을 쓴다.
  - 사진에서 EXIF를 제거한다.
- GoatCounter 방문자 통계는 그대로다.
- CSS 압축기 함정이 있다. `animation-timeline` 같은 속성이 `animation` 축약형으로 합쳐지면 브라우저가 규칙을 버린다. 길게 풀어 쓰고, 빌드 결과(dist)를 테스트로 확인한다.
- 모든 변경은 테스트를 먼저 쓰고(RED→GREEN), `npm test`와 `npm run test:dist`가 통과해야 한다.
- 사이드바 구조에 묶인 기존 dist 테스트(`.sidebar`, `.mobile-header`, `class="item"` 개수, `page-title` 등)는 새 구조에 맞게 고친다. 다만 **같은 의도**(현재 탭 표시, 한국어 페이지 영어 메뉴, 항목 수, 토글 없음, 전환 시 메뉴 고정)는 계속 검사해야 한다.

## 9. 만드는 사람에게 맡기는 것 [빌더]
- 컴포넌트를 어떻게 나누고 무엇이라 부를지 (예: `Sidebar` + `MobileHeader` → 하나의 `SiteHeader`)
- 정확한 간격, 최대 폭, 반응형 중간 폭(768–1100px)의 처리
- 장미색 글자의 대비 확보 방법
- 테스트를 새 구조에 맞게 옮기는 구체적 방법
- 404 페이지 세부
